# Cliplink

A URL shortener: one Astro app at the root, deployed to Vercel, with Postgres on Neon.

Run `pnpm check` (types, lint, format, Vitest) before saying you're done. Run `pnpm e2e` too when you change pages or routes.

## Read first

- `GLOSSARY.md`: the domain words (Link, Code, Destination, Owner, Visitor). Use them in code, tests, and copy.
- `docs/adr/`: decisions already made. Follow them, or write a new ADR to change one.
- Coding standards: `~/Projects/home-repo/docs/agents/coding-standards.md`.

## Module map

Feature modules, not layers (ADR-0005). Each module's `index.ts` is its public interface.

- `src/db`: Drizzle client (`createDb`), schema, and `createTestDb()` for Vitest. Migrations live in `drizzle/`.
- `src/links`: every Link rule (`createLinks({ db })` gives `createLink`, `listLinks`, `renameLink`, `deleteLink`, `deleteOwnerLinks`, `findDestination`) and the Link table. `src/links/destination.ts` and `src/links/name.ts` are also imported by islands, since `@/links` would bundle database code.
- `src/auth`: Better Auth (`createAuth`), its tables, the browser `authClient`, sign-in error messages, and the User name rule (`src/auth/name.ts`, safe for islands). Deleting a User runs `deleteOwnerLinks` first, in Better Auth's `beforeDelete`. Renaming goes through the `user.rename` Action, so Better Auth's own `/update-user` is turned off.
- `src/app.ts`: the app's `db`, `links`, and `auth` instances, built from `astro:env`. Pages, Actions, and middleware import from here.
- `src/middleware.ts`: puts the session on `Astro.locals` and sends Visitors on private pages to sign in.
- `src/actions`: Astro Actions. Thin: zod input, call a module, map its errors to `ActionError`.
- `src/components/links`: Link islands (home page form, copy button, rename and delete dialogs).
- `src/components/layout`: the site shell (layouts, navbar, footer, dark mode toggle). `src/components/ui` is generated by shadcn.
- `src/pages`: routes. `[code].astro` is the Redirect; static routes win over it.
- `scripts/cutover.sh`: the operator's wizard for production setup, cutover to cliplink.app, and rollback (`scripts/cutover.sh rollback`). Agents edit it, the operator runs it. Its checks live in `scripts/cutover/` (`checks.ts` is pure and tested, `verify.ts` does the I/O).
- `scripts/vercel-build/`: the build's migration guard (`should-migrate.ts` is pure and tested, `migrate.ts` runs it).
- `e2e/`: Playwright tests. `e2e/support/session.ts` signs a test in by writing a session row and its signed cookie.

## Testing

- Module tests are Vitest against PGlite through the module's public interface. Call `createTestDb()` once per test file and keep the ORM unmocked.
- Playwright runs against a production build. `@astrojs/vercel` has no preview server, so `E2E=1` swaps in the Node adapter. It loads `.env`, migrates `DATABASE_URL`, then starts the server. Set `E2E_PORT` when another worktree already uses 4321.

## Gotchas

- Keep `astro:*` imports out of `src/db` and other modules that drizzle-kit, Vitest, or Playwright load. Pass env values in.
- `createDb` uses node-postgres for localhost URLs, because the Neon driver can't reach plain Postgres (`pnpm db:dev`, CI).
- To render the 404 page with a 404 status, return `new Response(null, { status: 404 })` from a page. Endpoints skip that reroute, and `Astro.rewrite('/404')` fails because the 404 page is prerendered.
- After a schema change, run `pnpm db:generate` and commit the SQL in `drizzle/`.
- Vercel builds run `scripts/vercel-build/migrate.ts` before `pnpm build` (`vercel.json`). Production always migrates. A preview migrates only when its database host differs from `PRODUCTION_DATABASE_HOST` (a Preview variable the wizard sets), because with Neon preview branching off Vercel hands previews the production URL. Neon sets no variable that marks a branch, so comparing hosts is the only check a build can make. A preview without `PRODUCTION_DATABASE_HOST` skips migrations rather than guess.
- The build needs the six Better Auth variables (`BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, both Providers' client ID and secret) in every Vercel environment it runs in, Preview included.
- `src/auth/schema.ts` is Better Auth's generated schema minus `account.password`. Better Auth's schema check expects that column, so it is turned off; `src/auth/auth.test.ts` signs in against the real migrations instead.
- TypeScript is pinned to `~6.0`: `@astrojs/check` and `typescript-eslint` don't support 7 yet.
