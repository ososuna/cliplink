# Feature modules, not Clean Architecture layers

cliplink-rest and cliplink-ui both had a folder per Clean Architecture layer. Each operation needed an abstract datasource, a datasource implementation, an abstract repository, a pass-through repository implementation, a use-case class, a DTO, and a mapper. The tests mocked every one of those seams and still missed real bugs, such as missing ownership checks and Deleted Links that kept redirecting. Cliplink is now organised as a few deep modules by feature (`src/links`, `src/auth`, `src/db`), each with a small interface and its queries inside. Tests run those modules against real Postgres (PGlite) instead of mocks. Don't reintroduce repository or use-case layers: add a seam only where there is a second real implementation.
